# SmartStay — кейс 2 «Номер, который знает гостя»

Команда **team21** · Хакатон Sain × Школа 21

Репозиторий содержит серверную и клиентскую части приложения:
персональный план отдыха, управление номером через симулятор организаторов
и обработчик автоматического прогона `POST /run`.

## 1. Запуск

### Сервер на стенде

Корень репозитория содержит `main.py`, `start.sh`, `requirements.txt` и схемы.
Среда организаторов: Python 3.11, 512 МБ памяти, 1 CPU, без GPU.
Зависимости устанавливаются при сборке из `requirements.txt`.

Одна команда запуска из корня проекта:

```bash
bash start.sh
```

Она запускает `uvicorn main:app --host 0.0.0.0 --port "${PORT:-8000}"`.
Сервер отвечает на `GET /` и `GET /health`.
Адрес команды: https://team21.hack.be-healthy.tech.

| Переменная | Для чего используется |
|---|---|
| `TEAM` | Идентификатор команды, `team21` |
| `PORT` | Порт сервера; по умолчанию 8000 |
| `HACK_API_URL` | API организаторов, `https://hack-api.be-healthy.tech` |
| `LLM_BASE_URL` | Прокси модели, `https://bifrost.be-healthy.tech/v1` |
| `LLM_API_KEY` | Выданный командный ключ LLM, только на сервере |
| `LLM_MODEL` | Выданная модель, `gpt-6-luna` |
| `HACK_TEAM_TOKEN` | Командный токен для отдельного интерактивного dev-прогона |
| `HACK_UI_RECORD_ID` | Необязательная начальная просьба dev-набора для интерфейса |
| `SMARTSTAY_CLIENT_ORIGINS` | Допустимые адреса клиента через запятую; заменяет список CORS по умолчанию |
| `SMARTSTAY_LOCAL_SPEECH` | Только для локальной разработки: `1` включает Whisper; на стенде `start.sh` принудительно задаёт `0` |

Значения ключей предоставляются через окружение стенда. В репозитории их нет.
Онлайн-токен приходит в `Authorization` запроса `/run` и передаётся в API набора;
`HACK_TEAM_TOKEN` вместо него не подставляется.

Из корня проекта:


Для команды 21 файлы выданного набора в примере находятся в

### Клиент

Интерфейс: React / React DOM, JavaScript/JSX и CSS; сборка — Vite, менеджер пакетов — npm. Зависимости закреплены в `FrontEnd/my-app/package-lock.json`.

Нужна Node.js 22.12+ либо совместимая более новая версия. В другом терминале:

```bash
cd FrontEnd/my-app
npm ci --include=optional
npm run dev
```

Открыть http://localhost:5173. Для работы клиента с сервером стенда:

```bash
npm run dev:stand
```

Адрес стенда задан в `FrontEnd/my-app/.env.stand` через публичную переменную
`VITE_API_URL=https://team21.hack.be-healthy.tech/api`. Ключи и токены в
`VITE_*` не помещаются: эти значения доступны браузеру.

Для сборки с подключением к стенду:

```bash
npm run build:stand
npm run preview
```

Открыть http://localhost:4173. Обычный `npm run build` сохраняет локальный режим
с относительным `/api`. После изменения `VITE_API_URL` клиент нужно пересобрать.
Бэкенд разрешает CORS для localhost и 127.0.0.1 на портах 5173 и 4173.
Для другого адреса клиента задать `SMARTSTAY_CLIENT_ORIGINS` на сервере и
перезапустить его. Работа со стендом требует его доступности для команды.

На «Мой номер» выбрать гостя, при необходимости учесть историю и применить план.
Карточки показывают вечер, ночь и утро; кнопки переключения виртуального времени
в текущем интерфейсе отсутствуют. «Управление» и текстовый чат работают с тем же
заездом и текущим виртуальным временем симулятора.

Все команды чата отправляются на `/api/room/command`. Сервер сохраняет просьбы,
тексты ответов и подтверждённые изменения отдельно для каждого гостя в текущем
прогоне. Точные команды обрабатываются кодом; произвольные формулировки и
уточнения передаются модели вместе с историей. После ответа клиент перечитывает
состояние устройств. История находится в памяти сервера и теряется при его
перезапуске; это не постоянное хранилище переписки.

**Голос:** запись и плеер реализованы. Локально доступно распознавание через
Whisper, выключенное по умолчанию. Для разработки на ноутбуке см.
[SPEECH_SETUP.md](SPEECH_SETUP.md). В конкурсном запуске через `start.sh` Whisper
отключён: загруженные веса, включая речевые модели, запрещены правилами.
На стенде используется текстовый чат; голос через разрешённый прокси пока
не подключён. Клиент проверяет доступность распознавания до включения микрофона.
Для локальной записи нужны разрешение браузера и HTTPS либо localhost.

### Автоматический прогон и устройство решения

`POST /run` принимает `{"case":2,"dataset_code":"..."}` и входящий
`Authorization: Bearer ...`. Обработчик загружает весь набор через `getData`,
готовит предпочтения и сценарий для каждого заезда, обрабатывает просьбы
каждого пользователя в хронологическом порядке и возвращает HTTP 200 с
объектом `{"stays":[...],"requests":[...]}`. Количество записей не зафиксировано.
Для каждого заезда и каждой просьбы возвращается настоящий `session_id`.

- `extract_preferences.py`, `confirmed_settings.py`: предпочтения из анкеты
  и истории, восстановление подтверждённых настроек «как дома» и «как вчера».
- `guest_scenario.py`: сценарий вечера, ночи и утра с правилами R1–R8.
- `request_handler.py`, `guest_requests.py`: распознавание намерения и
  детерминированный расчёт допустимых частичных изменений.
- `case2_run.py`: обработка всего набора, отдельные сеансы, применение через
  API симулятора, проверка подтверждённых значений, история по пользователям.
- `interactive_room.py`, `interactive_guests.py`, `room_simulator.py`:
  самостоятельный dev-прогон интерфейса, планы, история чата и шесть устройств.
- `chat_commands.py`: точные команды карточек без обращения к модели.
- `deployment_settings.py`: CORS и флаг локального распознавания речи.

Внутри `/run` нет HTTP-вызова `validate`: проверяется только локальная JSON-схема.
В dev-инструментах `case2_dev.py` и `case2_dev_check.py` проверка формата
и сверка с открытым эталоном выполняются отдельно от рабочего обработчика.
Эталон не передаётся в модель и не используется для построения рабочего ответа.
Интерактивный интерфейс не изменяет закрытые сеансы зачётного `/run`.
После HTTP 409/410 он предлагает новый UI-сеанс; устаревший контекст отклоняется
с HTTP 412. Успех изменения требует подтверждения симулятора.

### Проверки и границы подтверждения

Из корня проекта после установки основных зависимостей:

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
```

В Windows вместо `python` можно использовать `py`. Сборка клиента запускается
из `FrontEnd/my-app`: `npm run build:stand`. Проверка линтером: `npm run lint`.

Проверка текущей рабочей папки 20.11.2026: **72 Python-теста и 16 Node-тестов
прошли**, сборка клиента для стенда прошла. Python-тесты выполнены локально на
Python 3.9; запуск этой версии на стендовом Python 3.11 в этой проверке не
выполнялся. Линтер `oxlint src` завершился с шестью предупреждениями React.
Тест цепочки «будильник на 07:30 → на час позже» проверяет передачу истории и
применение результата с имитацией ответа модели; это не тест живого LLM.

В предыдущих локальных проверках интеграции подтверждены чтение устройств,
применение плана и проверка состояния симулятора. **Исторические результаты
из отчёта команды:** живой dev-прогон обработал 5 заездов и 38 просьб и прошёл
проверку формата; первоначальная сверка дала 35/38, контроль после исправлений
с сохранёнными ответами модели и настоящим симулятором — 38/38. Эти цифры
относятся к предыдущей сборке, не перепроверены для текущей версии и не являются
оценкой организаторов. Отчёт команды указывает, что новый полный LLM-прогон
не был выполнен из-за исчерпания бюджета; актуальный остаток бюджета здесь
не проверялся. Свежий полный `/run` окончательной версии на стенде не подтверждён.

Новая LLM-персонализация и обработка произвольных просьб требуют доступного
командного бюджета. Разбор точных команд устройств, сна и пробуждения выполняется кодом.
Открытие базового плана интерфейса не вызывает LLM. Таймер звука сохраняется
как поле симулятора; его локальное автоотключение работает при открытом клиенте.

Дополнительные ограничения интерфейса:

- **Финальный пользователь пока не подключён к интерфейсу.** `/run` обрабатывает переданный набор отдельно, а интерфейс создаёт dev-прогон. Для финального показа нужно связать интерфейс с пользователем и сеансом финального набора; одного адреса стенда недостаточно.
- Голосовые сообщения хранятся в памяти страницы и исчезают после перезагрузки. Whisper доступен только в явно включённом локальном режиме. На стенде распознавание отключено; синтез голосового ответа не реализован.
- Экран «продолжение дома» не реализован. Подготовка персонального сценария за 10 секунд не подтверждена. В карточке кейса оба пункта относятся к пожеланиям.
- Выбор фонового звука управляет симулятором. Воспроизведение соответствующих фоновых аудиотреков в браузере не подтверждено; локальный плеер голосовых сообщений работает отдельно.
- Адаптивность проверялась в эмуляции Chrome на смартфонных и планшетных размерах, включая горизонтальную ориентацию. Проверка на физических устройствах и в iOS Safari не подтверждена.
- Запись, остановка, воспроизведение голосового сообщения и освобождение микрофона проверены в Chrome с тестовым источником звука. Результаты пользовательского тестирования не заявлены.

## 3. ИИ

**В конкурсном режиме:** `gpt-6-luna` через выданный прокси организаторов.
Модель извлекает предпочтения из текста и распознаёт намерения в произвольных
просьбах. Код проверяет структуру ответа, происхождение предпочтений, диапазоны
и допустимые поля, рассчитывает конкретные изменения и применяет их через
симулятор. Ошибка модели не считается успешным изменением номера.

Все рабочие обращения к модели используют `LLM_BASE_URL`, `LLM_API_KEY`,
`LLM_MODEL`. Общий ограничитель выдерживает паузу 2,5 секунды между стартами
вызовов в одном процессе; повторы ограничены. Командный бюджет разделяется
между участниками, разработкой и онлайн-прогоном.

Запись голоса в клиенте использует браузерные MediaRecorder и Web Audio API.
В локальном режиме распознавания запись преобразуется в WAV и отправляется
на Python-бэкенд, где используется Whisper small через pywhispercpp.

в зависимости стенда. Временный аудиофайл удаляется после обработки; плеер
хранит запись в памяти страницы. На стенде Whisper отключён независимо от
локальных настроек. Синтез голосового ответа не подключён.
